DESCRIPTION

i.ocean renders ocean areas of a raster map with a realistic visual appearance. It combines depth-based colour gradients, latitude-driven colour temperature, optional wave textures, physically-based ocean turbulence with coastal foam, and optional maritime decorations to produce a styled, floating-point output raster with an automatically tuned ocean colour table. The module is written in C with OpenMP parallelism and uses FFTW3 for spectral ocean surface synthesis. At least one of input or depth must be provided. Non-ocean pixels are set to null in the output so the result composites cleanly over any land base map when displayed with d.rast. Processing progress is reported as a percentage through both the terminal and the GRASS GUI progress bar. All raster computations use all available CPU cores automatically.

The input parameter specifies an ocean mask raster. Cells whose value equals ocean_value (default: 1) are treated as ocean; all other cells become null in the output.

The depth parameter specifies a bathymetric depth raster with positive values representing depth in metres below the surface (e.g. GEBCO). When depth is supplied it drives the colour gradient: shallow areas receive lighter, warmer colours and deep areas receive darker, cooler colours. When input is omitted, depth additionally defines the ocean extent by thresholding. When the depth map is stored as an integer raster (CELL type), it is automatically smoothed with a 3×3 neighbourhood average before normalisation to remove staircase artefacts from the rendered gradient.

The depth_min option sets the minimum value in the depth map that is considered ocean. Use 0 (default) for standard bathymetric maps. For DEM or elevation maps where negative values represent water, set depth_min to a negative value such as -0.1.

The latitude option sets the reference latitude in decimal degrees used to select the colour palette. When omitted the latitude is auto-detected from the centre of the current computational region.

The style option overrides the auto-detected latitude zone and forces a specific colour palette: auto, tropical, subtropical, temperate, subpolar, or polar.

The -w flag adds a sinusoidal wave texture. The wave period and amplitude are calibrated to the pixel size of the current computational region so that the result looks realistic at any scale.

The -s flag estimates a depth proxy from the Euclidean distance of each ocean pixel to the nearest land pixel using an in-memory two-pass distance transform (Meijster 2000).

The -l flag applies a subtle north–south warmth gradient across the scene, mimicking the visible sea-surface-temperature gradient.

The -f flag generates a physically-based ocean surface using the Phillips power spectrum computed by FFTW3. Foam appears where wave crests exceed a threshold, amplified near the coast via an exponential shore-proximity factor derived from a two-pass Euclidean distance transform.

The -d flag scatters maritime decorations across the ocean surface: whale, dolphin, fish school, octopus, treasure chest, floating crate, and sunken ship. Placement density is proportional to ocean area; a fixed-seed PRNG ensures reproducible results. A GRASS vector map is simultaneously created with the same name as the output raster, containing real-world-scale silhouette lines for each decoration. Use deco_scale to enlarge or shrink the vector silhouettes to match your map scale.

The module performs a RAM feasibility check before allocating raster buffers. When estimated peak usage exceeds 80 % of available memory the -f flag is automatically disabled with a warning. When it exceeds 95 % a fatal error is raised with advice to reduce the computational region.

NOTES

Ocean mask sources

The ocean extent can come from two sources:
  1. input mask — an existing raster in which one cell value marks water, specified with ocean_value.
  2. depth map alone — ocean pixels are identified as cells in the depth map whose value is at or above depth_min.
When both input and depth are provided, input defines the ocean extent and depth drives only the colour gradient.

Depth index

All depth information is normalised to a depth index ranging from 0 (shoreline) to 1000 (abyssal plain). Three strategies apply in priority order:
  1. depth map — absolute depths rescaled to 0–1000.
  2. -s flag — shore distance rescaled to 0–1000.
  3. Default — flat index of 500.

Integer depth smoothing

When the depth map is integer (CELL type), a 3×3 neighbourhood average converts it to DCELL before normalisation, eliminating staircase terracing in the rendered gradient. FCELL and DCELL maps are passed through unchanged.

Phillips-spectrum turbulence and foam (-f)

The ocean surface height field is generated using the Phillips power spectrum: 
  P(k) = A · exp(−1/(k·L)²) / k&sup4; · |k̂ · ŵ|²
where k is the wavenumber, L = V²/g is the dominant length scale from wind speed V, and ŵ is the unit wind direction. A 2-D real inverse FFT (fftw_plan_dft_c2r_2d) produces the spatial height field. Gaussian noise is generated per-thread with Box-Muller for thread safety. Coastal foam is amplified using an exponential decay factor applied to the shore distance field.

Maritime decorations (-d)

Each decoration type is rendered both as a small pixel-art raster stamp and as a real-world-scale vector silhouette. Vector shapes are derived from biological/historical data; small objects (treasure chest, floating crate) are bumped up to the dolphin minimum (3 m) so that all types share a homogeneous minimum ground footprint on the map. The 3D mesh reference for the sunken ship is the 0AD hele_ship_bireme.dae model (beam 8.8 m, length 49.2 m in-game), scaled to the canonical historical trireme dimensions.

Vessel silhouettes

The vector map draws the 17 vessel types (sunken trireme, war vessels, merchant ships) from smooth outlines: cubic Bézier hulls, arcs, ellipses and rounded rectangles, tessellated to about 1 m chords so that they stay smooth at any scale. Each vessel carries its deck details: forecastle break, cargo tanks with their hatches, pipe rack and manifold, hose cranes, the accommodation block with its bridge wings, funnel and lifeboats, Moss spheres, hatch covers, container bays and lashing bridges, cargo cranes, mooring arcs; for submarines a Myring hull with sail, sail planes, stern planes and rudder. Closed parts are written as areas, nested or apart, with their centroid at a point inside the part and clear of the parts drawn on it; open parts (pipes, cranes, lashing bridges) are lines. The attribute table gives each category its type, length, width and deco_scale.

RAM check and partial-load mode

Before allocating raster buffers the module reads /proc/meminfo (Linux) to compare estimated peak usage against available RAM:

  • < 60 % available — proceed normally.
  • 60–80 % — warning issued, processing continues.
  • 80–95 % — warning issued; -f (FFTW3 foam) is automatically disabled to reduce peak memory by ~3×.
  • ≥ 95 % — fatal error; use g.region to reduce the computational region.

The main memory consumers are: mask and depth-index buffers (2 × N × 8 bytes), FFTW3 complex and real arrays (~3 × N × 8 bytes), and the shore distance float array (N × 4 bytes), where N = rows × cols.

Multi-core parallelism

All inner row loops use #pragma omp parallel for with omp_get_max_threads() threads. Set OMP_NUM_THREADS to limit CPU usage.

EXAMPLES

Basic ocean rendering from a land/sea mask

r.mapcalc "sea_mask = if(elevation < 0, 1, null())"
i.ocean input=sea_mask output=ocean_view
d.rast map=ocean_view

Using a bathymetric depth map

Integer (CELL) depth maps are smoothed automatically. 
i.ocean depth=gebco_bathy output=ocean_view

Combining mask and depth with all effects

i.ocean input=sea_mask depth=gebco_bathy output=ocean_full \
        style=tropical -w -f -l -d
d.rast map=ocean_full

Overlaying ocean on a land hillshade

r.relief input=elevation output=hillshade
i.ocean input=sea_mask depth=gebco_bathy output=ocean_deep -w -f -l
d.shade shade=hillshade color=ocean_deep
